Moonbeam Academy demo

Everything here is fictional: one invented district, one school, two classrooms, invented children. Nothing is sent anywhere: email lands in the demo inbox, and the Microsoft and Google buttons on the sign-in page are simulated.

District Admin

Morgan Quillfeather: schools, classrooms, consent coverage, staff, security alerts, break-glass. Two-step sign-in is done for you.

Teacher

Class home, BC proficiency by skill, who may need support, launch a session, reports, roster import.

Parent

Sam Brightwater: sees only their own children (Juniper and Wren), in plain language.

Child (K–3)

Opens the class's student login (as the teacher would), then the normal flow: tap a name, and in Room 2–3 the secret picture. A secret picture is never shown anywhere: to try Room 2–3, first set a new one for a child as their teacher or parent.

More to try

  • Sign in by hand on the log-in page with any demo email and the password you set as LUMOS_DEMO_PASSWORD: admin@demo.lumos.test, teacher.k1@demo.lumos.test, teacher.23@demo.lumos.test, parent.1@demo.lumos.test, parent.2@demo.lumos.test, parent.3@demo.lumos.test.
  • Invite a teacher (District Admin) or a parent (Teacher → Manage a child), or use “Forgot your password?”: the email arrives in the demo inbox and its link works. Passwords on the simulated breach list (e.g. password1234) are refused.
  • Roster import (Teacher → class page): try the sample CSV (fictional, with a few deliberate mistakes).
  • Room K–1 children tap only their name; Room 2–3 children also tap a secret picture.

Reset the demo

To put every demo record back the way it started (including any password you changed), run in the project folder:

LUMOS_CONFIRM_DESTRUCTIVE=lumos npm run demo:seed

It only works on the demo database. The demo inbox empties when the server restarts.
